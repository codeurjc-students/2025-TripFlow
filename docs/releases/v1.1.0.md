# 📦 TripFlow - Release v1.1.0

---

> **🧭 Summary**
>
> Minor release **1.1.0** of **TripFlow**. Builds on the SEO groundwork from 1.0.2 to make the app fully discoverable and installable: public routes are now prerendered to static HTML at build time (so crawlers and social scrapers get real content, not an empty SPA shell), every public page ships its own title, description and Open Graph tags, and the PWA gains a native install button plus a richer install dialog. No backend behaviour changes — this is a frontend discoverability, installability, and build-pipeline release.

---

## 📄 Release Notes

### 🚀 Prerendering

- **Static prerender of public routes**: after `vite build`, a headless Chromium snapshots `/`, `/login`, `/signup`, `/help` and `/privacy` into static `index.html` files. Crawlers and link scrapers now receive fully rendered HTML instead of the empty `<div id="root">` shell. The client still renders normally for users.
- **nginx serving**: `try_files` now serves the prerendered pages directly (e.g. `/help`) without a trailing-slash `301`, keeping URLs consistent with the sitemap.

### 🔍 SEO & AI Agents

- **`sitemap.xml`** added with the 5 public routes, and referenced from `robots.txt`.
- **Per-route metadata**: a `useSeo` hook sets a unique `<title>`, meta `description` and `<link rel="canonical">` for each public page by mutating the tags already in `index.html` (no duplicates).
- **Open Graph / Twitter Cards**: default tags in `index.html` (overridden per route by `useSeo`) plus a 1200×630 `og-image.png`, so shared links render a proper preview on WhatsApp, X, Slack, etc.

### 📲 PWA & Installability

- **Install button**: a `useInstallPrompt` hook captures the browser's `beforeinstallprompt` event, surfaced through an `InstallButton` that self-hides when the browser can't offer installation (iOS, already installed, unsupported).
- **Placement**: the hero's primary call-to-action becomes "Instalar app" when installable, falling back to "Comenzar ahora" otherwise; a second install button sits in the "how to install" guide section.
- **Richer install dialog**: the manifest now declares a fuller `description` and `screenshots` — one desktop (`wide`) and two mobile (`narrow`) — so Chromium shows its enhanced install UI instead of the minimal prompt. Screenshots are excluded from the offline precache.

### 🌐 Infrastructure

- **Docker layer caching in CI**: `cd-build.yaml` now uses Buildx with GitHub Actions cache (scoped per service), so the Chromium install layer and other build steps persist across runs.
